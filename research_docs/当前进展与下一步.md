## 1. 当前阶段判断

当前已经明确学位论文的三个研究目标和两类数据的证据分工：

1. 受控—真实双场景稳定目标检测；
2. 实验室复杂飞行条件下的标准多目标跟踪；
3. 真实长视频分类计数与树莓派边缘运行。

当前研究已从“四个并列目标”收缩为一条完整链路：

> 跨场景检测保证看得见 → 实验室标准 MOT 验证跟得住 → 真实长视频验证数得准 → 树莓派验证跑得动。

第二篇论文的投稿范围已进一步收缩为“真实诱捕长视频分类计数”这一条证据线，负责回答“最终能不能数准”。跨场景检测器作为计数实验的冻结前端条件，树莓派部署则属于学位论文完整链路和系统验证内容，不再与分类计数并列为第二篇论文的核心贡献。

不再将“领域偏移分析”设为独立研究目标或必须独立章节，而是将受控域与真实域的差异融入统一目标检测章的设计、实验和失败分析。

在这条新的大论文主线下，第二篇论文的检测模型和最终计数方法尚未冻结。2026-07-25 用户撤回原 B0/E1/E2/E3 优化消融结构及其绑定的旧轨迹缓存重放方案，随后又明确根目录工程不得继续把 ByteTrack 作为隐含基准，且旧 `main.py` 只是 ByteTrack 计数可行性测试入口，应删除。当前链路改为“统一全帧检测缓存 → 8 个候选跟踪算法独立输出统一轨迹缓存 → 同一单圆计数器”。首轮 baseline 不使用 ROI，ROI 作为后续计数优化变量再研究。统一计数采用 2304×1296 参考画面中的圆心 `(1185, 732)` 和半径 `R=215 px`，但目前仍只是工程起点，不能视为论文最终方法或已经取得精度收益的结论。

### 2.3 当前检测—跟踪—计数工程链路

当前代码按三层解耦：

- 以 2304×1296 为参考画面，统一圆心 `(1185, 732)`、半径 `R=215 px`；其他分辨率按比例缩放；
- 首轮 baseline 统一使用全帧检测，不启用 ROI；ROI 不属于当前跟踪器选型的控制变量，留待后续计数优化单独研究；
- `detection_model_benchmark/cache_detections.py` 只执行全帧 YOLO 并逐帧写出检测缓存；8 跟踪器的 detection-only baseline 默认以 `conf=0.10` 保存共享缓存，使原生低分框恢复或分数增强不会在缓存阶段丢失输入；真正的跟踪阈值采用各算法官方默认值，SORT 原生无分数过滤；空帧也写入，目录输入递归扫描并在缓存中保留逻辑长视频的相对目录结构；不运行任何跟踪器或计数器；
- 8 个候选跟踪器为 SORT、ByteTrack、OC-SORT、SF-SORT、FastTracker、BoostTrack、HybridSORT 和 BoT-SORT，分别位于 `tracking_model_benchmark/01_sort...08_botsort/`；
- 统一跟踪输入为 `Nx6 [xyxy,confidence,class_id]`，统一输出为 `Nx8 [xyxy,track_id,confidence,class_id,detection_index]`；8 个官方实现的原生 API 差异全部封装在公共适配层；
- 每个候选读取同一全帧检测缓存，直接输出完整画面坐标的统一轨迹缓存；每个物理片段独立初始化；
- `counting_model_benchmark/replay_counting.py` 对所有算法的轨迹缓存使用同一框中心计数规则：同一 raw track ID 从圈外到圈内记 `+1`，从圈内到圈外记 `-1`；
- 使用有符号累计，不把负预测截断为 0；片段边界重置轨迹计数状态，同一逻辑长视频目录内计数连续累计；
- 根目录旧 BoxMOT ByteTrack 运行时与专用重放入口已删除；若 ByteTrack 最终最优，使用 `tracking_model_benchmark/02_bytetrack/` 的正式候选实现；
- 数值缓存采用原子写入和完整性校验，异常中断的半成品不会替换正式缓存。

## 3. 已经确认的关键计数问题

当前圆形边界基线计数实际上估计净跨界量：

```text
C = N_enter - N_exit
```

用户已确认正式人工真值是全部片段拍摄结束后的瓶内最终占用数。当前代码以从 0 开始的有符号净跨界量近似该真值，并允许预测为负数，不再用 `max(0, ...)` 截断误差。两者严格等价仍要求逻辑长视频开始时瓶内初始数量为 0；已在真实数据诊断中观察到三类独立误差源：

1. **初始占用/born-inside 误差**：轨迹首次出现在圈内时不计入，但后续退出仍减 1，会结构性产生负数；
2. **轨迹碎片化误差**：同一实蝇分裂为多个 raw ID，进入与退出不能在同一身份内相消；
3. **边界徘徊误差**：实蝇在边界附近往返，反复触发进入/退出事件。

另有一类物种统计误差：

4. **类别抖动误差**：同一轨迹的单帧物种预测变化，导致进入和退出被记录到不同物种。

已保留的 track 级诊断证据：

- `two-class_6_1`：50 条 raw track 产生计数事件，其中 15 条 born-inside track 的首事件为退出，恰好对应 15 条生涯净计数为 -1 的轨迹；最终进入 10 次、退出 15 次，净跨界量为 -5（correcta -1，dorsalis -4）；
- `two-class_5_6`：82 条 raw track，born-inside track 为 24 条；最终进入 29 次、退出 22 次，净跨界量为 +7（correcta -2，dorsalis +9）；
- 已观察到单条 raw track 触发 18 次进入/退出事件，证明边界徘徊会导致重复触发。

上述数值是对旧 `(1184,724), R=150` 配置的历史诊断摘要，不是当前 `(1185,732), R=215` 统一圆的结果，也不是正式测试集精度结论。原始输出曾位于 `project_results/result_two_class_79_27_individual/`，2026-07-25 已按用户要求清理，现只保留本文档中已提取的摘要。

当前统一实现已删除容差带、慢/快确认、类别投票、进入类别锁定和跨 raw ID 重连，因此尚未解决边界抖动、类别抖动、初始占用与轨迹碎片化。现阶段不能声称已经实现“长时程鲁棒计数”。

## 5. 当前建议的实验顺序

以下是新主线下的宏观实验顺序。当前不应直接启动正式计数实验；应先确定第二篇论文检测模型，再以当前统一全帧检测缓存/单圆链路为工程起点重新设计阶段 D，不再恢复已撤回的 B0/E1/E2/E3 结构。

### 阶段 A：冻结真值和数据划分

1. 按已冻结的“全部片段结束后瓶内最终占用数”定义，核验每个逻辑长视频开始时的 `N_start`；
2. 核对模型 class ID 到物种名的映射，并以 `ground_truth_v1.csv` v1.1 为权威真值；
3. 按采集批次/日期划分开发、验证和测试数据；
4. 记录视频与权重文件哈希。

### 阶段 B：构建统一跨场景检测器

1. 整理受控检测数据与真实检测数据的统一类别和标注；
2. 完成分别训练/测试、混合训练、跨域直接测试和预训练后微调；
3. 同时比较受控域 mAP、真实域 mAP、最差域精度、模型大小和复杂度；
4. 冻结一个用于后续跟踪与计数对比的统一检测器；
5. 生成可复用的逐帧检测缓存。

### 阶段 C：实验室标准 MOT 验证

1. 确认或完善实验室逐帧 ID 真值；
2. 按快速飞行、状态切换、遮挡和交汇等难点建立子场景标签；
3. 在相同检测条件下比较 SORT、ByteTrack、OC-SORT、SF-SORT、FastTracker、BoostTrack、HybridSORT 和 BoT-SORT；
4. 报告 HOTA、IDF1、MOTA、IDSW、轨迹碎片数和子场景性能；
5. 所有关联方法在验证集调参，测试集仅用于冻结后评价。

### 阶段 D：真实长视频计数

> 当前状态：真值已定义为最终瓶内占用数；检测器、8 个跟踪器的验证集参数和正式计数方法尚未冻结。现有全帧检测和 `(1185,732), R=215` 单圆瞬时跨界仅为工程起点；ROI 暂不纳入首轮 baseline。

1. 核验并记录每个逻辑长视频的初始瓶内占用 `N_start`；
2. 重新设计并验证初始占用、轨迹碎片、边界徘徊和类别抖动处理机制；
3. 使用同一检测缓存和同一计数器，仅替换跟踪器；
4. 在验证集上冻结方法和参数；
5. 在测试集报告分物种 MAE、Class-MAE、Total-MAE、完全正确视频比例、负计数比例和 FPS；
6. 如建立事件级真值，再补充进入/退出事件 Precision、Recall 和 F1。

### 阶段 E：树莓派实机验证

1. 将冻结的检测—跟踪—计数链路迁移到目标树莓派；
2. 比较 PyTorch/可行后端、ONNX、NCNN 及不同输入尺寸；
3. 评估跳帧、线程/队列和视频写出等系统策略；
4. 报告端到端 FPS、延迟、峰值内存、功耗和温度；
5. 完成长时间连续运行测试，记录崩溃、内存增长、丢帧、过热降频和计数偏差。

## 6. 当前不能声称的结论

在补齐真值、完整测试和树莓派实测前，不能在论文中声称：

- 当前全帧检测缓存/单圆瞬时跨界链路已经获得更高计数精度，或已经是论文最终方法；
- `yolo8n_two-class.pt` 或其他现有工程权重已经被选为第二篇论文检测模型；
- 当前方法已经完全解决负计数、初始占用或轨迹碎片化；
- 某跟踪器在真实视频中具有更高 HOTA、IDF1 或更少 IDSW；
- 实验室与真实场景的运动分布“一模一样”；
- 服务器上的 ONNX/NCNN 速度就是树莓派运行速度；
- 树莓派已经达到实时、低功耗和长时间稳定运行。
