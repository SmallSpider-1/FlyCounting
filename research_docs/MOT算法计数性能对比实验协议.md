# MOT 算法对最终计数性能影响的对比实验协议

> 建立日期：2026-07-14
> 实验性质：面向最终计数任务的下游性能对比，不是标准 MOT 基准评测。

## 1. 实验目的

本实验不制作逐帧目标身份（ID）真值，也不计算 HOTA、IDF1、MOTA、IDSW 等依赖 MOT 标注的指标。实验以逐视频人工计数真值为评价依据，在固定检测器和计数方法的条件下，仅替换 MOT 算法，比较不同 MOT 算法对最终分类计数准确率的影响。

本实验回答的问题是：

> 在相同检测结果和计数规则下，哪一种 MOT 算法能够使两类实蝇的逐视频计数误差最低？

实验结论只能表述为“某 MOT 算法在本数据集上获得了更好的下游计数性能”，不能据此宣称该算法具有更好的通用 MOT 性能。

## 2. 前置条件

### 2.1 冻结计数目标

正式实验前必须明确人工真值和算法输出估计的是同一个量，以下三者不能混用：

1. 累计进入数量：`N_enter`；
2. 净跨界数量：`N_enter - N_exit`；
3. 末帧区域占用数量：`N_start + N_enter - N_exit`。

用户已于 2026-07-25 确认：当前目录级逐物种数字表示该逻辑长视频全部片段拍摄结束后瓶内的最终数量，即末帧瓶内占用真值。算法侧以每个逻辑长视频从 0 开始的有符号计数 `N_enter - N_exit` 近似最终占用；退出允许把预测减为负数，不使用 `max(0, ...)` 隐藏错误。该近似成立的采集前提是逻辑长视频开始时瓶内初始数量为 0；如实际初始数量非 0，必须登记 `N_start` 并纳入预测。

### 2.2 冻结目标检测器

MOT 对比前先确定并冻结一个目标检测模型，包括：

- 模型结构和权重；
- 输入区域和输入尺寸；
- 置信度阈值；
- NMS/端到端后处理方式及阈值；
- 推理精度模式；
- 类别名称和类别 ID 映射。

推荐先把每帧检测结果缓存下来，再将同一份检测结果分别输入不同 MOT 算法，从而避免重复推理造成差异，并保证跟踪器接收到完全相同的检测框、类别和置信度。缓存字段、完整性校验、失效条件和重放入口统一遵循 `检测-跟踪-计数数值缓存与重放协议.md`。

## 3. 对比算法

首轮计划比较以下算法：

| 算法 | 角色 | 是否使用目标域 MOT 标注 |
|---|---|---:|
| SORT | 经典运动关联基线 | 否 |
| ByteTrack | 候选算法 | 否 |
| OC-SORT | 运动关联对比 | 否 |
| SF-SORT | 候选算法 | 否 |
| FastTracker | 候选算法 | 否 |
| BoostTrack | 无 ReID/ECC 的纯数值受控变体 | 否 |
| HybridSORT | 候选算法 | 否 |
| BoT-SORT | 无 ReID/GMC 的纯数值受控变体 | 否 |

如果某算法使用预训练分割器、ReID 或其他辅助模型，应在实验配置中完整记录。允许使用公开预训练权重，但不得使用本实验测试视频的 ID 标注进行训练或微调。

如果某算法无法接收冻结的同一份检测结果，或者必须更换检测器才能运行，则该结果不再属于严格的“仅替换 MOT 算法”对比，应单独列为“端到端系统对比”，不能与受控 MOT 对比混在同一张主表中。

## 4. 控制变量

除 MOT 算法及其内部必要参数外，下列条件必须完全一致：

- 目标检测模型和权重；
- 每帧检测结果；
- 输入视频文件及其字节内容；
- 视频帧率和处理帧序列；
- 计数区域、边界位置和坐标变换；
- 进入/退出事件判定规则；
- 初始占用处理方式；
- 类别投票和类别锁定规则；
- 每个视频独立初始化；
- 最终计数量的定义。

为了保证调参公平，每种 MOT 算法使用相同的验证集和相近的调参预算。禁止根据测试集计数结果反复修改参数。

## 5. 数据划分

数据必须以完整视频为单位划分，不能将同一视频的不同片段同时放入验证集和测试集。

- 开发集：检查程序、日志和计数链路；
- 验证集：调整各 MOT 算法参数并选择最终算法；
- 测试集：算法和参数冻结后仅运行一次，报告最终结果。

如果不同视频来自同一次连续采集，优先按采集批次或采集日期划分，降低相邻视频内容泄漏的风险。

## 6. 真值格式

推荐建立独立真值文件：

```text
video,class_id,count,annotator,version,count_definition
```

其中：

- `video`：视频文件名或唯一标识；
- `class_id`：类别 ID；
- `count`：该视频、该类别的人工计数真值；
- `annotator`：标注者；
- `version`：真值版本；
- `count_definition`：`cumulative_enter`、`net_crossing` 或 `final_occupancy`。

两类实蝇的类别 ID 与文件名数字顺序必须显式记录，避免将 *B. correcta* 与 *B. dorsalis* 对调。

## 7. 评价指标

设测试视频数量为 `N`，类别集合为 `C={correcta,dorsalis}`；`y(i,c)` 为第 `i` 个视频类别 `c` 的人工真值，`p(i,c)` 为算法计数结果。

### 7.1 分类别 MAE

```text
MAE(c) = (1/N) * sum_i |p(i,c) - y(i,c)|
```

分别报告：

- `correcta MAE`；
- `dorsalis MAE`。

### 7.2 分类计数 MAE

```text
Class-MAE = (1/(N*|C|)) * sum_i sum_c |p(i,c) - y(i,c)|
```

该指标同时惩罚两个类别的误差，适合作为物种特异性监测任务的主要选择指标。

### 7.3 总数 MAE

```text
Total-MAE = (1/N) * sum_i |sum_c p(i,c) - sum_c y(i,c)|
```

总数 MAE 衡量两类实蝇合计数量的误差。它不是两个类别 MAE 的平均值，也可能因类别间误差抵消而偏低。例如将两个类别分别多算 3 和少算 3 时，总数误差为 0，但分类计数仍然错误。因此不能只使用总数 MAE 选择算法。

### 7.4 完全正确视频比例

只有一个视频中两个类别的计数都与真值完全相等，才记为完全正确：

```text
Exact-Video-Rate = 完全正确视频数 / N
```

### 7.5 可选诊断指标

在不增加 MOT ID 标注的前提下，可以同时记录：

- 产生负计数的视频比例；
- 每个视频的进入数和退出数；
- 未配对退出数；
- 计数误差随视频时长的变化；
- 处理 FPS。

这些指标用于解释计数误差来源，不作为 MOT 标准指标。

## 8. 算法选择规则

如果研究目标是按物种分别计数，建议按照以下优先级在验证集选择算法：

1. `Class-MAE` 最低；
2. 分类别 MAE 较均衡，避免某一物种误差特别高；
3. `Exact-Video-Rate` 最高；
4. `Total-MAE` 最低；
5. 在准确率接近时，再比较处理速度和部署成本。

算法选定并冻结全部参数后，再在测试集上进行最终评价。

## 9. 实验流程

1. 人工核验计数真值的语义和类别顺序；
2. 按完整视频或采集批次划分开发集、验证集和测试集；
3. 冻结检测器、检测参数和计数规则；
4. 对全部视频生成并保存统一检测缓存；
5. 将相同检测缓存分别输入各 MOT 算法；
6. 使用同一计数器生成逐视频、逐类别结果；
7. 在验证集调整各算法参数并选择最终算法；
8. 冻结算法与参数，在测试集运行一次；
9. 汇总计数指标、逐视频结果和失败案例。

工程执行时使用“原视频 → 全帧检测缓存 → 各候选跟踪缓存 → 同一计数器”的分层链路。首轮 baseline 不启用 ROI，ROI 只作为后续计数优化的独立变量。公共接口固定为检测 `Nx6 [xyxy,confidence,class_id]` 输入和轨迹 `Nx8 [xyxy,track_id,confidence,class_id,detection_index]` 输出，具体入口为 `detection_model_benchmark/cache_detections.py`、`tracking_model_benchmark/_common/run_tracker.py` 和 `counting_model_benchmark/run_counting_benchmark.py`。8 个候选当前均采用无 ReID、无 GMC 的纯数值变体；若后续增加依赖 ReID、掩膜或原始纹理的方法，必须读取冻结视频帧或统一缓存外观特征，并单独记录输入依赖。

若算法包含随机过程，应固定随机种子；若固定种子后仍不能保证确定性，则至少重复运行 3 次，并报告均值和标准差。

## 11. 结果表述边界

允许的结论：

> 在固定检测器和计数规则的条件下，算法 A 在独立测试视频上取得最低的分类计数 MAE，说明其跟踪输出更适合本研究的实蝇计数任务。

不允许的结论：

> 算法 A 的 MOT 性能优于所有其他算法。

由于实验没有逐帧身份真值，不能评价通用轨迹完整性、身份保持能力或标准 MOT 排名。实验只验证不同 MOT 算法对最终计数结果的影响。
