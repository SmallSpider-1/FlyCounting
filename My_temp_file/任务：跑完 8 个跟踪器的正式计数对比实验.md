## 第三步：跑剩下 7 个

一次命令加一个跟踪器，**不要用 --trackers all 一把梭**：

```
python counting_model_benchmark/run_counting_benchmark.py \
  --detections project_results/detection_cache/rtdetr_r18_official_v1 \
  --output <同一个输出目录> \
  --trackers bytetrack
```

顺序：bytetrack → ocsort → sfsort → fasttracker → boosttrack → hybridsort → botsort。

关于这样跑的机制，你需要知道：

- 运行清单 `benchmark_run_manifest.csv` 是**增量追加**的，同一个输出目录跑多次不会丢前面的结果。清单里已有同名跟踪器会报错，这是防重复的设计，不是 bug。
- 某个跟踪器跑崩了，**不要放弃整轮**。记下报错原文和是哪个片段崩的，跳过它继续跑后面的。8 个里崩了几个、崩在哪，最后一起报告。
- 不要用 `--overwrite`，也不要用 `--purge`。这两个是重跑用的，本次是首次跑。真需要重跑某个跟踪器时先报告原因。
- 用 `nohup` 或 `tmux` 后台跑，每个跟踪器一份独立日志，日志路径写在报告里。不要让长任务因为终端断开死掉。
- 每个跟踪器跑完就报一次它的计数结果和真值对比，不要攒到最后。
